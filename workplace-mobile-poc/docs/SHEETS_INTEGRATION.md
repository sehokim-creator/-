# 구글 시트 연동 — 설정 가이드

현재 총무 업무는 스프레드시트에서 운영되고 있고, 화면은 아직 POC 데이터로 동작합니다.
이 문서는 **시트를 읽어오는 경로**를 붙이기 위해 필요한 작업을 정리합니다.

읽기 전용입니다. 시트에 쓰지 않습니다. 화면이 완성되기 전까지 스프레드시트가 계속
원본(source of truth)이어야 하고, 포털 버그가 실제 운영 데이터를 망가뜨리는 일이 없어야
합니다. 쓰기는 운영 DB가 레코드를 소유한 뒤에 검토합니다 (핸드오프 P-003).

---

## 1. 세호님이 해주셔야 하는 것

### 1-1. GCP 프로젝트와 서비스 계정

1. Google Cloud Console에서 프로젝트를 만들거나 기존 프로젝트를 선택합니다.
2. **Google Sheets API**를 사용 설정합니다 (API 및 서비스 → 라이브러리 → Google Sheets API → 사용).
3. **서비스 계정**을 만듭니다 (IAM 및 관리자 → 서비스 계정 → 만들기).
   - 역할은 부여하지 않아도 됩니다. 시트 접근은 아래 4번의 공유로 결정됩니다.
4. 서비스 계정에서 **키 → 새 키 만들기 → JSON**을 내려받습니다.
   JSON 안의 `client_email`과 `private_key`가 필요합니다.

> 사내 정책상 서비스 계정 생성이 제한될 수 있습니다. 그 경우 인프라/보안팀에
> "Sheets 읽기 전용 서비스 계정" 발급을 요청하는 편이 빠릅니다.

### 1-2. 시트 공유

각 스프레드시트를 **서비스 계정 이메일**(`...@....iam.gserviceaccount.com`)에
**뷰어(보기 권한)** 로 공유합니다. 편집 권한은 주지 마세요 — 읽기만 하면 됩니다.

### 1-3. 시크릿 등록

배포 환경에 아래 3개를 **시크릿으로** 등록합니다. 저장소에 커밋하지 마세요.

| 이름 | 값 |
| --- | --- |
| `GOOGLE_SA_EMAIL` | 서비스 계정 `client_email` |
| `GOOGLE_SA_PRIVATE_KEY` | 서비스 계정 `private_key` (`-----BEGIN PRIVATE KEY-----` 포함) |
| `GOOGLE_SHEETS_ID` | 스프레드시트 URL의 `/d/` 다음 문자열 |

Cloudflare Workers면 `npx wrangler secret put GOOGLE_SA_EMAIL` 형태로 넣습니다.
로컬은 `.dev.vars` 또는 셸 환경변수를 씁니다. `private_key`의 줄바꿈은 `\n`
그대로 둬도 코드에서 복원합니다.

### 1-4. 시트 구조 확정 (가장 중요)

`lib/sheets-source.ts`의 `sheetBindings`에 시트별 **탭 이름·범위·헤더 텍스트**가
가정값으로 들어가 있습니다. 실제와 다르면 그 필드는 `null`이 됩니다.
아래를 알려주시면 제가 맞추겠습니다.

- 각 시트의 **탭 이름** (예: `출입카드`)
- **헤더 행의 정확한 텍스트** (예: `카드번호`인지 `카드 번호`인지)
- 헤더가 1행이 아니라면 몇 번째 행인지
- 병합 셀·소계 행·피벗이 섞여 있는지

### 1-5. 정책 결정 필요

- **접근 통제**: 이 API는 지금 인증이 없습니다. 실제 데이터를 붙이기 전에 사내
  SSO(Okta)를 앱 앞단에 두고, 라우트에서 서버측 멤버십 검사를 해야 합니다.
  화면의 로그인은 데모용이라 우회 가능합니다.
- **개인정보 범위**: HR·구성원 시트를 그대로 노출할지, 필요한 컬럼만 뽑을지.
  현재 설계는 필요한 컬럼만 매핑하는 방식입니다.
- **동기화 주기**: 요청 시 조회(현재, 60초 캐시) / 주기적 스냅샷 / 웹훅.
  시트는 웹훅이 없어서 주기 조회가 현실적입니다.

## 2. 이미 구현해 둔 것

| 파일 | 내용 |
| --- | --- |
| `lib/sheets-source.ts` | 시트→앱 필드 매핑, 셀 파싱(원화·퍼센트·날짜·불리언), 정규화 |
| `app/api/sheets/[id]/route.ts` | 서비스 계정 JWT 서명 → 토큰 교환 → 지정 범위 읽기 |
| `tests/sheets-source.test.mjs` | 파싱·매핑 단위 테스트 6건 (`npm run test:unit`) |

설계상 신경 쓴 지점:

- **헤더 텍스트로 매핑합니다.** 위치(A열·B열)로 읽지 않기 때문에 시트 중간에 열을
  끼워 넣어도 값이 밀리지 않습니다.
- **시트 변경을 숨기지 않습니다.** 응답에 `missingHeaders`(매핑했는데 시트에 없는
  헤더)와 `unmappedHeaders`(시트에 있는데 매핑 안 된 헤더)를 함께 반환합니다.
  누가 헤더 이름을 바꾸면 조용히 빈 값이 되는 대신 드러납니다.
- **키 없는 행은 버리고 셉니다.** 소계·빈 행이 레코드로 새지 않게 하고,
  버린 개수를 `skipped`로 알려줍니다.
- **환경변수가 없으면 503 + `configured: false`** 를 반환합니다. 자격증명이 없는
  상태에서도 화면은 POC 데이터로 계속 동작합니다.

### 동작 확인

```bash
npm run test:unit                      # 파싱·매핑 테스트
npm run dev                            # 개발 서버
curl localhost:5173/api/sheets/access-cards   # 미설정: 503 configured:false
curl localhost:5173/api/sheets/nope           # 없는 바인딩: 404
```

## 3. 다음 단계 (권장 순서)

1. 시트 하나(예: 정기주차권 입차율)만 먼저 연결해 파이프라인을 검증합니다.
   개인정보가 없고 구조가 단순해서 첫 대상으로 적합합니다.
2. 그 화면에서 실제 값이 맞게 나오는지 확인한 뒤 나머지 바인딩을 채웁니다.
3. 그다음 SSO와 서버측 권한 검사를 붙입니다. 그 전에는 구성원·비용 시트를
   연결하지 않는 편이 안전합니다.
4. 마지막으로 운영 DB로 이관합니다. 시트는 그때 원본에서 내려옵니다.
